# powerautomate-startup — Power Automate Desktop フローをテキストで開発するスタートキット (padkit)

## なぜ

PAD (Power Automate Desktop) のフローはデザイナー上でしか編集できず、
テキストとしてレビュー・再利用するのが難しい。padkit は:

- **レシピ (`*.pad`) + プロファイル (JSON)** から環境ごとのフローテキストを生成する
- 貼り付け前に **PAD バージョン依存の構文落とし穴を lint で検査** する
- 実行中のデザイナーへの **クリア・貼り付け・エラーチェック・実行を自動化** する

AI 補助が使えない環境でも、決まったコマンドだけでフローを再現できることを目指す。

## クイックスタート

```bash
git clone <このリポジトリ> && cd powerautomate-startup
dotnet build -c Release   # → src/PadKit.Cli/bin/Release/net8.0-windows/padkit.exe

# サンプルレシピをレンダリング (examples/README.md 参照)
padkit render-all examples --profile examples/profiles/sample.json --out-dir out

# 貼り付け前チェック (バージョン依存ルールに違反していないか)
padkit lint out/*.txt

# PAD デザイナーを開いた状態で実機チェック (クリア→貼付→エラー数)
padkit designer check out/01-run-cli-to-csv.txt
```

## 対象バージョン

- .NET SDK 8.0 / Windows
- PAD **11.2609.183.0** で貼り付け・実行まで実機検証済み
  (lint ルールは `rules/pad-11.2609.json` に切り出してある)

## 免責

PAD のアクション識別子・引数名はバージョンで変わることがある。
別バージョンでは赤枠が出る場合があるため、rules/*.json とブロックを自分の
バージョンに合わせて見直すこと (デザイナーでアクションを開けば引数名が分かる)。

## 他プロジェクトからの使い方

自分のリポジトリに `recipes/` `profiles/` を置き、このリポジトリの
`blocks/` を `--blocks` で指すかコピーして使う。padkit.exe は
このリポジトリで一度ビルドすればどこへでも持ち出せる (単一 exe)。

```bash
padkit render-all <your-repo>/recipes --profile <your-repo>/profiles/env.json \
    --blocks <このrepo>/blocks --out-dir <out>
```

## 構成

```

```

## CLI

```
padkit render <recipe.pad> --profile <p.json> [--profile <p2.json>]... [--out <file>] [--blocks <dir>]...
padkit render-all <recipes-dir> --profile <p.json> [--profile <p2.json>]... --out-dir <dir> [--blocks <dir>]
padkit lint <file>... [--rules <json>] [--json]
padkit blocks [--blocks <dir>]
padkit designer windows | status | dump [--depth N] | clear | paste <file>
                | check <file>... | run <file> [--timeout <sec>] [--json]
```

- `render`: レシピ 1 件をレンダリング。`--out` 無しなら stdout。lint 指摘は stderr。
  エラー級の指摘があれば exit 1。生成先頭に `# generated by padkit ...` を付与。
  `--profile` は複数回指定可 (後勝ちオーバーレイ。例:
  `--profile dev.json --profile dev.local.json` でローカル秘密値だけ上書き)。
- `render-all`: ディレクトリ内の全 `*.pad` を `<out-dir>/<name>.txt` へ。
- `lint`: 指摘を `file:line: RULE severity message (fix: ...)` 形式で表示。
- `blocks`: 解決可能なブロックと引数の一覧。
- `designer check`: `クリア → 貼り付け → アクション数/エラー数` をファイルごとに
  `name: actions=N errors=M` で出力 (エラーがあれば本文を最大 12 件表示、exit 1)。
- `designer run`: check → errors=0 なら保存 → 実行 → `run: started=… finished=…` を出力。
  エラー時は実行せず exit 2。

終了コード: `0` 正常 / `1` 指摘・検査失敗 / `2` 使い方・実行エラー。

## テンプレート構文 (*.pad レシピ)

通常行はそのまま PAD フローテキストとして出力される。

- `#! requires: Key1 Key2` (先頭コメント部のみ有効): プロファイル値を
  `#` ヘッダ直後へ `SET Key TO $'''値'''` (文字列、`\` は二重化) /
  `SET Key TO <値>` (数値・真偽値) として挿入。未提供キーはまとめてエラー。
- `{{> block-name key="value"}}` (独立行): ブロック本文に展開。
  行頭の空白は全出力行へ継承されるので `IF`/`LOOP` 内でも使える。
  値中の `"` は `\"` でエスケープ。ブロック内からの入れ子 include は深さ 8 まで。
- ブロック内の `{{key}}` が引数参照。展開後に残った `{{...}}` は E_UNRESOLVED エラー。
- ブロックファイル先頭の `#! param <Name>` / `#! param <Name> default="..."` が引数宣言
  (default 無しは必須)。`#!` 行は本文から除去される。
- ブロック探索順: `<レシピのdir>/blocks/` → `--blocks` → padkit 同梱 `blocks/`
  (`PADKIT_BLOCKS` 環境変数、未設定なら exe から上へ `blocks/`+`PadKit.sln` の親を探索)。
- プロファイル = JSON オブジェクト 1 枚。値は生の Windows パス (`C:\work` を
  JSON では `C:\\work`) で書き、バックスラッシュの二重化はレンダラーが行う。

## lint ルール (rules/pad-11.2609.json, PAD 11.2609.183.0 で実機検証)

scope: `code` = `$'''...'''` の外側、`string` = 内側、`line` = 行全体。`#` コメント行は対象外。

| id | sev | scope | 内容 | 修正 |
|---|---|---|---|---|
| PAD001 | error | code | 旧 2 セグ名 `System.RunDOSCommand` | `Scripting.RunDOSCommand.RunDOSCommand` |
| PAD002 | error | code | 2 セグメント識別子 (`twoSegmentAllow` 以外) | 3 セグメント `Module.Action.Variant` へ |
| PAD003 | error | code | `Display.Icon.Error` (解析不能) | `Warning` 等に |
| PAD004 | error | code | `CSVFilePath:` | `CSVFile:` |
| PAD005 | error | code | `File.WriteText ... FilePath:` | `File:` |
| PAD006 | error | code | `SET X TO %...` (式の `%` 囲み) | `%` を外す |
| PAD007 | error | string | 文字列中の `%式%%` | 直後の `%` を全角 `％` に |
| PAD008 | error | code | `ON BLOCK ERROR` | `LOOP WHILE`+`IF`+`WAIT` で代替 |
| PAD009 | error | line | `LoopIndex` | カウンタ変数を使う |
| PAD010 | error | code | `ReadAllCells ... FirstLineContainsColumnNames:` | `FirstLineIsHeader:` |
| PAD011 | error | code | `RunApplication ... Timeout:` | 引数削除 |
| PAD012 | warning | code | `InvokeWebService EncodeRequestBody: True` | `False` に |
| PAD013 | warning | code | `Excel.CloseExcel.Close` (未検証) | `CloseAndSave` に |
| PAD100 | error | — | IF/LOOP と END の不対応、IF 外の ELSE、迷子 END (C# 実装) | 構造修正 |
| PAD101 | error | — | 未解決の `{{` 残留 (C# 実装) | 引数を直す |

## ルール・ブロックの追加方法

- **正規表現ルール**: `rules/pad-11.2609.json` の `rules[]` に
  `{ "id", "severity", "scope", "pattern", "message", "fix" }` を 1 件追加。
  新しいバージョン向けには `rules/pad-<version>.json` を複製して作り、
  `lint --rules` または `render --rules` で指定。
- **2 セグメント許可識別子**: 実機で貼り付けが通った 2 セグメント名を
  `twoSegmentAllow[]` に追加するだけでよい。
- **ブロック**: `blocks/<name>.pad` を作り、先頭に `#! param` 宣言、続きに本文。
  本文中の `#` コメント行は PAD 側にも残るので非エンジニア向けの説明を入れておく。
  追加後は `padkit blocks` で一覧確認、`padkit lint` のゴールデンテスト
  (tests/PadKit.Tests/GoldenTests.cs) で回帰を確認。

## AutomationId 一覧 (PAD 11.2609.183.0 で dump 確認)

| AutomationId | 用途 |
|---|---|
| `DesignerMainWindow` | デザイナーのトップレベルウィンドウ |
| `ProgramItemsListBoxActions` | アクションキャンバス (List)。子は ListItem×アクション |
| `ProgramItemTemplateSummaryTextBlock` | 各アクションの概要テキスト (アクション数の裏付け) |
| `ProgramDetailsStatusBarItem` | ステータスバーの件数表示 (`N 選択/アクション/サブフロー`) |
| `ErrorCountTextBlock` | エラー件数 (エラーがあるときのみ出現) |
| `Flow_status_ready` 等 | ステータス表示 (`Flow_status_` 接頭辞 + running/parsing/ready) |
| `SaveDraftFlowButton` | ドラフト保存ボタン |
| `StartFlowButton` / `StopFlowButton` | 実行/停止 |
| `EmptyState` | 空キャンバス中央のオーバーレイ (クリックの当たり判定に注意) |

注意: キャンバス中央は EmptyState オーバーレイでフォーカスが取れないため、
`FocusCanvas` はキャンバス上部 (top+80px) をクリックする実装になっている
(座標は BoundingRectangle から算出、ハードコードなし)。

## 注意

- `designer` 系コマンドは実行中の PAD デザイナーへ接続する (先にデザイナーを開く)。
- Save/Run 中に UIA が一時タイムアウトすることがあるため Status はリトライ実装。
- Webhook URL 等の秘密情報はプロファイルへ直接書かず、gitignore したローカル
  プロファイルで管理すること。
